# Day4. Локальная LLM как код-ассистент в AstroNvim против облака

Дата: 2026-10-26. Железо: Apple M4 Max, 36 GB. LM Studio, codecompanion.nvim 20.0.1, minuet-ai.nvim, AstroNvim v5, nvim 0.11.5.
Облачная база: результаты Day1 и Day2 (`claude-opus-5-5`, Claude Code 2.1.310). Версии и sha256 лежат в [env.txt](env.txt).

## Итог

| | Облако (Day1/Day2) | qwen3-coder-30b (MoE 30B-A3B) | qwen3.8-27b (dense), thinking выкл. |
|---|---|---|---|
| **Агентная задача** (bug-fixer Дня 2) | PASS с 1-й попытки, 85 с, 20 ходов | 0 из 3 попыток: шаблон без работы / подгон теста / пустой фикс | **PASS с 1-й попытки**, 7 мин, 14 запросов (с thinking: FAIL, 22 мин) |
| **Генерация фичи** (бот Дня 1) | все проверки PASS, покрытие 86.9%, black-box 14/14, review 30/32, 525 с | FAIL: тесты не собираются (testify), токен в логе, 21 мин | FAIL: не уложилась в 60 мин, конверт Telegram API не разобран, black-box 0/14 |
| Скорость генерации | — (облако, ~1.5–9 мин на задачу) | ~40–60 tok/s | ~12–13 tok/s |

**Рекомендация.** Локальной модели хватает на точечную работу в одном-двух файлах с понятной проверкой: фикс бага по симптому, тест к функции, рефакторинг, объяснение кода, FIM-автодополнение. Тут работает связка **qwen3.8-27b без thinking + T 0.2 + 32k**. Облако незаменимо там, где нужно с нуля собрать проект из 20+ файлов по большому своду правил, держать контракт внешнего API и довести дело до зелёных тестов без присмотра. Обе локальные модели на такой задаче оставили нерабочий код и при этом отчитались об успехе (coder30b прямо, 27b не успела).

## Что настроено

Исходник конфига: [nvim/ai.lua](nvim/ai.lua). Он подключён symlink'ом в `~/.config/nvim/lua/plugins/ai.lua` через [nvim/install.sh](nvim/install.sh). Прежний файл сохранён как `ai.lua.bak.20261025231052`.

| Что | Как |
|---|---|
| Чат, inline, агент | codecompanion, адаптер `lmstudio` (OpenAI-compatible, `http://127.0.0.1:1234`), агентный режим `@{agent}`. Модель по умолчанию `qwen/qwen3-coder-30b`, переключение через `AI_CHAT_MODEL` или `ga` в чате |
| Автодополнение | minuet + blink.cmp, FIM на `qwen2.5-coder-1.5b`: T 0.1, 56 токенов, 2048 символов вокруг курсора |
| **Файл правил в system prompt** | Ближайший к cwd `.ai/system-prompt.md` (поиск вверх до `$HOME`) дописывается в system prompt чата и агента в теге `<project_rules>`. Здесь это [.ai/system-prompt.md](.ai/system-prompt.md), побайтная копия `Day1/variant-b/CLAUDE.md` (594 строки, ~9–10k токенов, sha256 `4a8e5756…`). Файл читается только как текст. Если правила занимают больше 40% окна, выводится предупреждение |
| **Какие файлы видит модель** | По умолчанию codecompanion сам подкладывает `AGENTS.md`, `CLAUDE.md`, `.cursorrules` и **`~/.claude/CLAUDE.md`**: в локальную модель уехал бы личный глобальный профиль. Автозагрузка правил выключена, в контексте только system prompt с правилами, буфер, из которого открыт чат (diff), и то, что модель сама прочтёт инструментами в пределах cwd |
| **Контекст** | Окно 32768 токенов. Оно задано и в LM Studio (`:AILoad` загружает модель с этим `-c`), и в `meta.context_window` адаптера, чтобы codecompanion знал лимит: сжатие старых tool-результатов с 65% окна, compaction с 85%. Вывод одного инструмента ограничен 6000 токенами (по умолчанию 30000, это почти всё окно) |
| **Параметры генерации** | Пресет на модель: T 0.2, top_p 0.9, top_k 20, max_tokens 8192. У qwen3.8-27b `reasoning_effort = "none"`: thinking выключен, см. ниже. В схеме `openai_compatible` этих полей не было, они добавлены в адаптер |
| Агентный промпт | Свой, короче стандартного: «работай до конца, проверяй сборкой и тестами, вопросов не задавай, допущения перечисли». В него встроены правила проекта |
| Профиль Дня 2 | `/bugfix` в prompt library: системное сообщение из [prompts/bug-fixer.md](prompts/bug-fixer.md) (тело `Day2/profiles/bug-fixer.md` без frontmatter) + инструменты агента |

## Методология

- **Те же задачи.** Генерация фичи: [tasks/feature.txt](tasks/feature.txt), побайтно `Day1/prompt.txt`. Правила те же, что у облачного варианта B. Агентная задача: [tasks/agent-bugfix.txt](tasks/agent-bugfix.txt), побайтно `Day2/tasks/bugfix.txt`, на копии `Day2/src` с профилем bug-fixer.
- **Прогоны через тот же IDE-конфиг.** [harness/driver.lua](harness/driver.lua) открывает в headless nvim чат codecompanion с `ai.lua` пользователя, `@{agent}` и approval `yolo` и отправляет задачу одним сообщением. Повторных подсказок нет: что модель сделала до первого финального ответа, то и результат («с первого раза»). Инструмент `ask_questions` убран, потому что в Дне 2 у облака тоже не было AskUserQuestion.
- **Изоляция.** [harness/run.sh](harness/run.sh): одноразовая копия в `$TMPDIR/d4run.*` (git init + тег baseline). Перед каждым прогоном модель перезагружается в LM Studio с нужным контекстом. nvim работает под **Seatbelt** ([harness/sandbox.sb](harness/sandbox.sb)): писать можно только в каталог прогона, сеть закрыта, кроме localhost, `~/.ssh`, `~/.claude`, `.env` и другие секреты не читаются. Это не формальность: coder30b в feature-прогоне пытался `GOPROXY=direct go mod tidy`, а обе модели запускали запрещённый профилем `gofmt -w`. В отличие от Claude Code, у codecompanion в yolo нет allowlist команд, и границу держит только песочница.
- **Измерения.** Логирующий прокси [harness/proxy.py](harness/proxy.py) между codecompanion и LM Studio сохраняет точные тела запросов, usage, TTFB и время (`requests.jsonl.gz`). Скорость считается по этим логам.
- **Проверки те же, что у облака, без изменений.** Feature: `Day1/compare/metrics.sh` и black-box стенд Day1 (`-src`). Bugfix: `Day2/harness/checks/bugfix.sh` (B1–B8, скрытый приёмочный тест). Плюс ручное review: `runs/*/*/manual.txt`.

### Ограничения

- **n мало.** coder30b на bugfix прогнан 3 раза, остальные комбинации по 1 разу. Подбор temperature/top_p и размера контекста (16k/64k) **не делался**: по решению пользователя этот этап и отдельный бенч скорости сняты. Сравнивались только две модели и параметр thinking вкл./выкл. при T 0.2 и 32k.
- **Сравнивается связка, а не только модель.** Облако работало в агентном цикле Claude Code, локальные модели в цикле codecompanion: другие инструменты, промпт и обработка ошибок.
- **Агентная задача неравная в пользу облака.** Локально в system prompt есть ещё и правила Дня 1 (~10k токенов поверх профиля), потому что в IDE они действуют всегда. В Дне 2 у облака был только профиль.
- Интерактивная проверка в nvim глазами не делалась (тоже снята). Конфиг проверен headless: загружается, system prompt собирается, правила на месте, глобального профиля в запросе нет.

Главные дефекты ([coder30b](runs/feature/coder30b-c32k-t0.2-1/manual.txt), [27b](runs/feature/q38-27b-c32k-t0.2-nothink-1/manual.txt)):
- coder30b нарушил «только stdlib» (`stretchr/testify` в тесте) и не убрал его, когда `go mod tidy` не прошёл без сети. Токен Telegram попадает в ERROR-лог через `*url.Error`, хотя правила требуют redact. В корне остался собранный бинарь на 8.7 MB.
- 27b декодирует `getUpdates` прямо в `[]Update` вместо конверта `{"ok":…,"result":…}`. Против настоящего API бот не отвечает ни на что, а собственный тест это скрывает, потому что мок отдаёт голый массив.

## Для чего хватает локальной

**Хватает** (qwen3.8-27b, thinking выкл., T 0.2, 32k; для автодополнения qwen2.5-coder-1.5b FIM):
- Фикс бага по симптому в 1–2 файлах с чёткой проверкой тестом. Обязательно смотреть diff: модели правят существующие тесты.
- Тест к существующей функции, локальный рефакторинг, объяснение кода, review небольшого diff.
- Автодополнение строк и блоков в редакторе.
- Работа без сети и с кодом, который нельзя отдавать наружу.

**Облако незаменимо:**
- Новый проект или фича на 10+ файлов по большому своду правил. У локальных моделей правила «съедают» окно, и детали контрактов теряются.
- Задачи, где нужно довести до зелёного без присмотра и честно отчитаться. Локальный агент может закончить с красными тестами и написать «готово».
- Длинные агентные циклы: на 27b круг идёт минуты, на coder30b быстро, но нестабильно (из 3 одинаковых запусков 3 разных провала).

**Что не делать:** включать thinking у qwen3.8-27b при низкой temperature (зацикливается в reasoning) и пускать агента в yolo без песочницы.
