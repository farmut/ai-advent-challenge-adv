# 03. Баг: после перезапуска бот повторно отвечает на последние сообщения

**Тип:** bug
**Код:** `Day5/src`
**Где:** `internal/delivery/telegram/poller.go:39-76` (`Poller.Run`)

## Шаги
1. Запустить бота, отправить `Казань`, дождаться ответа.
2. Сразу остановить бота (Ctrl+C / SIGTERM), не дожидаясь следующего цикла long polling.
3. Запустить снова.

## Ожидаемо
Повторного ответа на `Казань` нет.

## Фактически
Telegram считает апдейты подтверждёнными, только когда приходит следующий `getUpdates` с `offset = last+1`.
После обработки пачки `Run` вызывает `GetUpdates` уже с отменённым `ctx`, поэтому запрос не уходит, offset
не подтверждается, и после рестарта Telegram отдаёт ту же пачку ещё раз. Пользователь получает дубль ответа.

## Критерии «сделано»
- [ ] При выходе по отмене `ctx`, если offset сдвинулся, poller делает один подтверждающий вызов `getUpdates`
      с `offset` и `timeout=0` на отдельном контексте с коротким таймаутом (не больше 5 с).
- [ ] Ошибка подтверждающего вызова логируется (WARN) и не меняет результат `Run` (`context.Canceled`).
- [ ] Если ни одного апдейта не было (offset == 0), подтверждающего вызова нет.
- [ ] Тест в `poller_test.go`: fake `UpdatesGetter` фиксирует вызовы; после отмены последним идёт вызов с
      ожидаемым offset.
- [ ] `go test -race ./...`, `go vet ./...`, `gofmt -l .` — чисто.
