# 14. Документация: doc-комментарии к доменным ошибкам

**Тип:** docs
**Код:** `Day5/src`
**Где:** `internal/domain/errors.go`

## Сейчас
Пять экспортируемых ошибок (`ErrInvalidCity`, `ErrCityNotFound`, `ErrProviderAuth`, `ErrRateLimited`,
`ErrProviderUnavailable`) без doc-комментариев. Из кода неясно, кто какую ошибку возвращает и что видит
пользователь. `go doc` по ним пуст.

## Критерии «сделано»
- [ ] У каждой ошибки есть doc-комментарий, начинающийся с её имени (Go convention).
- [ ] Комментарий отвечает на два вопроса: кто возвращает (usecase / адаптер провайдера, при каком HTTP-статусе)
      и как ошибка должна обрабатываться выше (показать пользователю конкретный текст / залогировать и показать
      «сервис недоступен»).
- [ ] Комментарии соответствуют коду: `statusError` в `openweather/client.go`, `respond` в
      `telegram/handler.go` (проверить вручную).
- [ ] `go doc -all ./internal/domain` выводит описание каждой ошибки.
- [ ] Код не изменён, только комментарии; `go vet ./...`, `gofmt -l .` — чисто.
