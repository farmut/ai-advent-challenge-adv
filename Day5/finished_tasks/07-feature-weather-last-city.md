# 07. Фича: /weather без аргумента повторяет последний город чата

**Тип:** feature
**Код:** `Day5/src`
**Где:** `internal/delivery/telegram/handler.go:60-82` (`respond`)

## Сейчас
`/weather` без города всегда отвечает `msgEmptyCity`.

## Нужно
Бот помнит последний город, для которого в этом чате **успешно** пришла погода, и `/weather` без аргумента
повторяет запрос для него. Хранение — в памяти процесса, с тем же ограничением размера, что и карта rate limit
(`maxTrackedChats`), чтобы память не росла бесконечно.

## Критерии «сделано»
- [ ] `Казань` → погода; затем `/weather` (через > 2 с) → погода в Казани.
- [ ] Неуспешный запрос (`ErrCityNotFound`, `ErrInvalidCity`, ошибка провайдера) последний город не меняет.
- [ ] В чате без истории `/weather` → `msgEmptyCity` (как сейчас).
- [ ] Город одного чата не виден в другом (тест на два `chatID`).
- [ ] Число хранимых чатов ограничено; есть тест на вытеснение.
- [ ] Доступ к хранилищу потокобезопасен; `go test -race ./...` чисто.
- [ ] `msgHelp` и README описывают новое поведение.
- [ ] `go vet ./...`, `gofmt -l .` — чисто.
