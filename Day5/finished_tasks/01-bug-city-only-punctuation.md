# 01. Баг: город из одних знаков препинания отвечает «сервис недоступен»

**Тип:** bug
**Код:** `Day5/src` (все пути ниже — относительно этого каталога)
**Где:** `internal/usecase/weather.go:44-58` (`normalizeCity`)

## Шаги
1. Отправить боту `---` (или `.`, `,`, `- . ,`).

## Ожидаемо
Ответ `msgInvalidCity` («Название города может содержать только буквы…»), запрос к OpenWeatherMap не уходит.

## Фактически
`normalizeCity` пропускает строку без единой буквы: разрешены символы ` -.,`, но наличие буквы не требуется.
Запрос уходит в OpenWeatherMap, тот отвечает 400/404, пользователь получает «⚠️ Сервис погоды сейчас недоступен»,
а в логе появляется лишний WARN `weather request failed`.

## Критерии «сделано»
- [ ] `normalizeCity` возвращает `domain.ErrInvalidCity`, если в городе нет ни одной буквы (`unicode.IsLetter`).
- [ ] В `TestWeatherServiceCurrentInvalid` добавлены кейсы `"---"`, `"."`, `" , . "`; для них `provider.calls == 0`.
- [ ] Валидные города с дефисом и точкой (`Ростов-на-Дону`, `St. Petersburg`) по-прежнему проходят (есть тест).
- [ ] `go test -race ./...`, `go vet ./...`, `gofmt -l .` — без ошибок и вывода.
