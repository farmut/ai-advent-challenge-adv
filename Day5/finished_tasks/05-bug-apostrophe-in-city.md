# 05. Баг: города с апострофом отклоняются как некорректные

**Тип:** bug
**Код:** `Day5/src`
**Где:** `internal/usecase/weather.go:52-56`, текст `msgInvalidCity` в `internal/delivery/telegram/messages.go:14`

## Шаги
1. Отправить боту `N'Djamena` (или `Val-d'Or`, `Sant'Agata`, `N’Djamena` с типографским апострофом U+2019).

## Ожидаемо
Погода в городе (или «не нашёл город», если провайдер его не знает).

## Фактически
Апострофа нет в списке разрешённых символов ` -.,`, ответ «Название города может содержать только буквы,
пробел, дефис, точку и запятую».

## Критерии «сделано»
- [ ] `normalizeCity` разрешает `'` (U+0027) и `’` (U+2019); остальные ограничения (длина, управляющие
      символы, цифры, `&`, `/`) не ослаблены.
- [ ] `TestWeatherServiceCurrentValid` содержит оба варианта апострофа.
- [ ] Тест-кейс `query inject` (`a&appid=x`) по-прежнему возвращает `ErrInvalidCity`.
- [ ] Тест в `openweather/client_test.go`: город с апострофом корректно экранируется в query (`q` на сервере
      совпадает с исходной строкой).
- [ ] `msgInvalidCity` упоминает апостроф.
- [ ] `go test -race ./...`, `go vet ./...`, `gofmt -l .` — чисто.
