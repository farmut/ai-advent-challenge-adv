# 04. Баг: /start и /help расходуют лимит запросов погоды

**Тип:** bug
**Код:** `Day5/src`
**Где:** `internal/delivery/telegram/handler.go:45-58` (`Handle`), `:84-99` (`allow`)

## Шаги
1. Отправить `/help`.
2. Меньше чем через 2 секунды отправить `Казань`.

## Ожидаемо
Погода в Казани. Лимит «1 запрос в 2 секунды» защищает внешний API погоды, а `/start`, `/help`, неизвестные
команды и пустой `/weather` в OpenWeatherMap не ходят.

## Фактически
`allow` вызывается до разбора команды, поэтому `/help` занимает окно, и на `Казань` приходит
«⏳ Не так быстро, попробуй через пару секунд».

## Критерии «сделано»
- [ ] Лимит проверяется и обновляется только перед вызовом `WeatherGetter.Current`.
- [ ] `/start`, `/help`, неизвестная команда, `/weather` без города отвечают всегда, независимо от лимита.
- [ ] Два запроса погоды подряд быстрее 2 с по-прежнему дают `msgTooFrequent` на второй (существующий
      `TestHandlerRateLimit` зелёный).
- [ ] Новый тест: `/help`, затем сразу `Казань` → второй ответ — погода, `WeatherGetter` вызван 1 раз.
- [ ] README (раздел «Команды») уточняет, что лимит касается только запросов погоды.
- [ ] `go test -race ./...`, `go vet ./...`, `gofmt -l .` — чисто.
