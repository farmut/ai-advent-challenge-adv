# 02. Баг: бот отвечает на команды, адресованные другому боту

**Тип:** bug
**Код:** `Day5/src`
**Где:** `internal/delivery/telegram/handler.go:101-113` (`parseCommand`)

## Шаги
1. Добавить бота в группу вместе с другим ботом `@OtherBot`.
2. Отправить в группу `/weather@OtherBot Казань` или `/help@OtherBot`.

## Ожидаемо
Наш бот молчит: команда адресована не ему.

## Фактически
`parseCommand` отрезает суффикс `@...` не глядя на имя, поэтому `/weather@OtherBot Казань` обрабатывается как
`/weather Казань`, а `/help@OtherBot` — как `/help`. Два бота отвечают на одну команду.

## Критерии «сделано»
- [ ] Handler знает username своего бота (получить через Bot API `getMe` при старте или из конфигурации — решение
      описать в комментарии к коду).
- [ ] Команда с суффиксом `@<чужое имя>` игнорируется: `Sender.Send` не вызывается, rate limit не расходуется.
- [ ] Команда с `@<своё имя>` (сравнение без учёта регистра) и команда без суффикса работают как раньше.
- [ ] Табличный тест в `handler_test.go` покрывает три случая: свой бот, чужой бот, без суффикса.
- [ ] `go test -race ./...`, `go vet ./...`, `gofmt -l .` — чисто.
