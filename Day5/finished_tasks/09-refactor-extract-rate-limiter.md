# 09. Рефакторинг: вынести per-chat rate limiter из Handler

**Тип:** refactor
**Код:** `Day5/src`
**Где:** `internal/delivery/telegram/handler.go:30-42`, `:84-99`

## Проблема
`Handler` совмещает разбор команд, вызов usecase и ограничение частоты (мьютекс, карта `lastReq`, вытеснение).
`Handle` вызывает `time.Now()` напрямую, поэтому лимит в тестах нельзя проверить без реального времени
или прямого вызова приватного `allow`.

## Нужно
Отдельный тип (например `chatLimiter` в том же пакете или своём файле) с методом `Allow(chatID int64) bool`
и внедряемыми часами (`now func() time.Time`). `Handler` получает лимитер через конструктор или поле.

## Критерии «сделано»
- [ ] В `Handler` нет полей `mu` и `lastReq`; логика лимита живёт в отдельном типе в отдельном файле.
- [ ] В `handler.go` нет вызова `time.Now()`.
- [ ] Тесты лимитера используют фейковые часы: без `time.Sleep`, окно и вытеснение проверены.
- [ ] Поведение бота не изменилось: все существующие тесты зелёные, их ожидания не правились (допустима
      только замена способа создания `Handler`).
- [ ] Публичный API пакета (`NewHandler` и его использование в `main.go`) либо не изменился, либо изменение
      описано в комментарии к PR/коммиту.
- [ ] `go test -race ./...`, `go vet ./...`, `gofmt -l .` — чисто.
